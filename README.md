# moNa2 — GT1 / GT2 / GT3 / ST / Key Override

## ダウンロード

- **[純正トラックボール版ZIPをダウンロード](https://github.com/ogimah/moNa2-RMK-gesture/releases/latest/download/moNa2-stock-bundle.zip)**
- **[COROPIT版ZIPをダウンロード](https://github.com/ogimah/moNa2-RMK-gesture/releases/latest/download/moNa2-COROPIT-bundle.zip)**

左右のUF2・使い方・ライセンスをまとめたZIPです。GitHubへのログインは不要です。
[配布ページ・更新内容を見る](https://github.com/ogimah/moNa2-RMK-gesture/releases/latest)


moNa2をお使いの方に、トラックボールの操作を少し広げる改変ファームウェアをご紹介します。興味を持ち、ここまで読みに来てくださってありがとうございます。普段の作業にどう取り入れられそうか、想像しながら見ていただけたらうれしいです。

押すキーで使い分けるジェスチャと、押している間だけ有効になるスクロールを備えています。
**v0.2では、Vialで設定できるKey Overrideと、エンコーダーのホイール出力対策を追加しました。**
moNa2（Seeed XIAO nRF52840構成）向けの非公式RMKファームウェアです。

## 押すトリガーで、3組のジェスチャを使い分ける

GT1・GT2・GT3を好きなキーに割り当て、押しながらトラックボールを上下左右に動かすと、設定した操作を実行できます。

**レイヤーを切り替えず、押すトリガーを変えるだけで3組のジェスチャを使い分けられます。**

1レイヤーに **3トリガー×4方向＝12種類**。さらにレイヤーごとに割り当てを変えられるので、CADなど、多くのコマンドを扱うソフトにも合わせて配置できます。

## カーソルとスクロールを、同じレイヤーで

通常はカーソル移動、**STを押している間だけ縦スクロール**。離すとカーソル操作に戻ります。

マウス操作用のレイヤーで、カーソル移動とスクロールを使い分けることを想定していますが、**STはどのレイヤーにも配置できます。**

マウスボタンやジェスチャと一緒にまとめても、普段使うレイヤーの押しやすい位置に置いても使えます。スクロール専用レイヤーへの切り替えは不要です。

## 割り当ては画面から

RMKを基盤とし、**キー配置・GT/STの配置・ジェスチャの出力・マクロ・タップダンスをVial／Pipetteから設定できます。** これらの割り当て変更に、ソース編集や再ビルドは必要ありません。

タップダンスも、タップ・長押し・2回タップなどの動作を画面で指定できます。限られたキー数でも、自分に合った操作を組み立てられます。

設定にはVialのほか、**Pipetteもおすすめです。** まずは使いやすい位置にトリガーを置き、普段の作業に合わせて少しずつ調整してみてください。

| 純正 | moNa2-stock-bundle.zip | moNa2-central.uf2 | moNa2-peripheral.uf2 |

上のダウンロードリンクから対応するZIPを取得し、展開してください。
ZIPには左右のUF2、説明、変更内容、著作権・ライセンス表示、SHA256SUMSが入っています。

## 2. 書き込む

1. 現在の設定を残す場合は、Vialで `.vil` ファイルを保存します。
2. 片側ずつUSB接続し、リセットを素早く2回押してブートローダードライブを表示します。
3. 右にはCentral、左にはPeripheralのUF2をコピーします。
4. 再起動後、右をUSB接続し、Vial / Pipetteを再接続して新しい定義を読み込みます。

コピーエラーが出た場合、完了したと判断せず再接続と動作を確認してください。
この版への更新時は、保存済み設定やBluetoothペアリングが初期化される場合があります。
更新前に `.vil` を保存し、必要に応じて更新後の読み戻し・再ペアリングを行ってください。

## 3. Vial / PipetteでGT・STを設定する

好きなレイヤーの物理キーを選び、ユーザタブのカスタムキーを割り当てます。

| 表記 | 押している間の動作 |
| --- | --- |
| GT1 | トラックボールの4方向を左の仮想十字へ出力 |
| GT2 | トラックボールの4方向を中央の仮想十字へ出力 |
| GT3 | トラックボールの4方向を右の仮想十字へ出力 |
| ST | トラックボールの縦移動をスクロールに変換 |

GTを配置したレイヤーで、対応する仮想十字の上下左右にキーやマクロを設定してください。
出力は現在の有効レイヤーと透過設定に従います。トリガー自体のレイヤー固定はありません。
編集後は自分の `.vil` として保存してください。

アンロックを求められたら、右側の最上段両端（初期配列のY/P位置）を同時に押します。

### ジェスチャ

- 移動量 `abs(X)+abs(Y)>30` で即発火。大きい軸を採用し、同値なら横方向。
- 押したまま150ms以上の間隔で次の動きを検知できます。解放自体では出力しません。
- GTとSTの同時押しはGT優先。
- 異なる番号のGTを複数押した場合は、1種類になるまで出力を止めます。
- 検知中の移動は通常カーソルへ漏れません。

### スクロール

- ST押下中のみ有効。横移動は無視し、解放すると通常カーソルへ戻ります。
- 縦8カウントでホイール1単位。CPI800、方向はRMK既定（invert_y=false）。
- 画面上の方向・移動量はOSやアプリ設定にも依存します。
- 解放・モード切り替え時は移動の端数を破棄します。
- 速度・方向をVialから変更する機能はありません。

## 4. VialでKey Overrideを設定する

修飾キーとの組み合わせに応じて、押したキーを別のキーへ置き換えられます。**Overrideは32枠、初期設定はすべて空**です。以下はVialの表示名で説明します。

例として「普段はテンキー1、Ctrlを押しているときだけCtrl＋通常の1」を設定します。

| 項目 | 設定 |
| --- | --- |
| Enable | ON |
| Enable on layers | 全レイヤー（用途に応じて限定も可能） |
| Trigger | テンキー1（KC_KP_1 / KC_P1） |
| Trigger mods | 左Ctrl・右Ctrl |
| Negative mods | すべてOFF |
| Suppressed mods | **すべてOFF**。押しているCtrlを残します |
| Replacement | 通常の1（KC_1）。Ctrlを追加で付ける必要はありません |

**Enableだけでなく、Optionsの開始条件もONにしてください。** 上から次の3項目をON、残りはOFFにします。

- **Activate when the trigger key is pressed down**：Ctrlを押してからテンキー1を押すと置換を開始。
- **Activate when a necessary modifier is pressed down**：テンキー1を押してからCtrlを追加しても開始。
- **Activate when a negative modifier is released**：除外指定の修飾キーを離したときに開始。この例は除外指定なし。

最初は1件だけ設定して動作を確かめ、必要な数字へ広げてください。同じ組み合わせをコンボにも割り当てている場合は、重複するコンボを無効にして確認します。編集後は `.vil` として保存してください。

## 初期配列・設定

標準配列は8レイヤーです。基本レイヤーはQWERTYで、数字レイヤー・設定レイヤーがあります。
一部キーはタップとホールドで動作が異なるMT/LTです。
配列はVialのキーマップ画面で確認できます。ソースのkeyboard.tomlにも各レイヤーを記載しています。

- TD・マクロ・コンボ・Overrideの設定は空。TD32枠・Override32枠などの編集容量は保持しています。
- GT1 / GT2 / GT3 / STと仮想十字12方向は未割り当てです。
- エンコーダーはPageDown / PageUp。その他レイヤーでは透過です。

## エンコーダー・接続

エンコーダーのマウスホイール割り当ては、回転イベントごとの1回出力として扱い、キーを押し続けるホイール処理へ持ち越さないようにしています。純正トラックボール・COROPITの両方で、従来スクロールが続いていた条件で停止することを確認しています。

RMK 0.9.0を基盤に、エンコーダーの信号取得修正も取り込んでいます。左右のバッテリー測定にも対応しますが、残量の表示方法はOSや接続先によります。設定方式はVialのままで、Rynkは有効にしていません。

## 検証情報・ソースからのビルド

GT/ST・Override・ホイール対策は、純正トラックボール版とCOROPIT版の個人用設定で実機確認済みです。配布用初期設定については自動検査と左右ビルドを行っています。
配布用初期配列での実機動作は、ビルド結果とは別に確認してください。

Rust 1.96.0と固定した依存バージョンを使用し、`cargo make uf2` でビルドします。
`python3 scripts/package_distribution.py` で同梱物・依存一覧・UF2・ハッシュを検査してZIPを作成します。
依存を変更した場合は、ライセンス一覧の更新が必要です。
